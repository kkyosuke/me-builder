# 設計スコープのルール

## 1. 現在の設計段階

現在は、プロジェクト概要と中核ドメインの構想を整理する段階です。

作業対象:

- AccountとBrainの責務・境界
- Brain内部情報の大分類
- Topic LabelとAccess Labelによる用途分離
- MCP提供時の高レベルなアクセス原則
- MVPと今後の設計順序

## 2. 明示的な依頼なしに深掘りしないこと

- 質問・回答の具体的なエンティティや集約
- AI推定結果と根拠の具体的なモデル
- MCP接続クライアント、Scope、監査レコードの具体的なモデル
- データベース、テーブル、コレクション、インデックス
- API、MCPツール、イベントの具体的なスキーマ
- 認証・認可製品の選定
- LLM、Embedding、検索エンジンの選定

これらは存在しないものとして扱うのではなく、後続設計へ意図的に延期します。

## 3. 設計時の判断

- ユーザーが求めた抽象度を越えない
- 候補を確定案として記載しない
- 実装詳細でドメインの責務を決めない
- 新しい概念を追加する前に、既存の分類や責務で表現できないか確認する
- 詳細化が必要な場合は、所有するSSoTを先に決める
- 設計内容を複数文書へ展開せず、[ドキュメント運用ルール](documentation.md)に従う

## 4. 現在の参照先

各概念の参照先と所有文書は、SSoTである[Agent向けガイドのドキュメントマップ](../README.md#ドキュメントマップ)で確認します。この文書には一覧を再掲しません。
