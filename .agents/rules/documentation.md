# ドキュメント運用ルール

## 1. 最重要原則

**1つの概念に対して、詳細を定義する文書は1つだけにします。SSoTを死守してください。**

別の文書でも説明が必要な場合は、SSoTへの相対リンクを置きます。利便性のために定義、一覧、表、ルールをコピーしてはいけません。

## 2. 文書ごとの責務

文書の所有範囲は[Agent向けガイドのドキュメントマップ](../README.md#ドキュメントマップ)を正とします。

所有関係をこの文書へ再掲してはいけません。追加・変更はドキュメントマップだけに行います。

## 3. 重複を作らない

禁止すること:

- 同じ分類一覧を複数文書へ掲載する
- SSoTの表を別文書へコピーする
- 同じ不変条件やルールを言い換えて複数箇所で定義する
- READMEへ詳細設計を書く
- 参照先と異なる用語や件数を要約側で独自に記載する

許可すること:

- SSoTの役割を1〜2文で説明する
- 概念名だけを使い、定義はリンク先へ委ねる
- 読む順序を示すナビゲーションリンクを置く
- 文書の責務と非対象範囲を明記する

短い要約を置く場合も、新しい規則や数値を追加してはいけません。

## 4. SSoTの変更手順

1. 変更対象の概念を所有する文書を特定する
2. 所有文書を先に変更する
3. `rg`で同じ用語、表、旧名称を検索する
4. 他文書に重複があれば削除してSSoTへのリンクへ置き換える
5. READMEと[Agent向けガイド](../README.md)のリンクを確認する
6. `git diff --check`を実行する

SSoTを移動する場合は、同じ変更で次を行います。

1. 新しい所有文書へ内容を移す
2. 古い所有文書から定義を削除する
3. 古い場所に新しいSSoTへのリンクを置く
4. ドキュメントマップを更新する
5. リポジトリ全体から古いリンクと重複を取り除く

## 5. 新しい文書を追加する条件

新しい文書は、既存文書と異なる明確な所有範囲がある場合だけ追加します。

追加時に必須の内容:

- 文書の目的
- 所有する概念
- 所有しない概念
- 関連するSSoTへの相対リンク
- [Agent向けガイドのドキュメントマップ](../README.md#ドキュメントマップ)への登録
- 必要に応じた[README](../../README.md)からのリンク

## 6. リンクのルール

- リポジトリ内文書には相対リンクを使う
- リンク先のファイル名を変更した場合、同じ変更ですべての参照を更新する
- 見出しリンクを使う場合、リンク先の見出し変更も確認する
- リンクだけでは意味が分からない場合、リンク前に1文だけ役割を書く
- 存在しない将来文書へのリンクを作らない

## 7. 用語のルール

- 同じ概念には同じ名前を使う
- 日本語の説明を基本とし、ドメイン用語は`Account`、`Brain`、`Access Label`のように表記を統一する
- 用語名を変更したら`rg`で旧名称を検索して残さない
- 未決定の概念を確定した名称や型として記載しない
- 例と正式なルールを明確に区別する

## 8. 図解・視覚化のルール

- アーキテクチャ、ディレクトリ構造、データフローなどを説明する際は、テキスト文章だけでなく図（Mermaid 図や ASCII Tree 図など）を用いてわかりやすく表現します。
- モノレポ構造やディレクトリツリーを示す場合は `tree` 形式の ASCII コードブロックを用いて視覚化します。
- コンポーネント間のデータフローやインフラ構成を示す場合は Mermaid ダイアグラム（`flowchart TD`, `sequenceDiagram` 等）を用います。

## 9. レビューのチェックリスト

- [ ] 変更した概念のSSoTは1つか
- [ ] 他文書に同じ一覧・表・定義をコピーしていないか
- [ ] 要約側がSSoTと異なるルールを持っていないか
- [ ] 関連文書へ相対リンクで移動できるか
- [ ] READMEとAgent向けガイドから必要な文書へ到達できるか
- [ ] 旧名称と古いリンクが残っていないか
- [ ] 未決定事項を確定案として書いていないか
- [ ] 構造やデータフローが図（Tree図やMermaid図）でわかりやすく表現されているか
- [ ] 現在の設計スコープを越えていないか
- [ ] `git diff --check`が成功するか
