# サービス利用規約・同意残タスク

## 1. 目的

この文書は、[サービス利用規約・同意体験設計](../product/service-terms-consent-experience.md)と[サービス利用規約の公開運用](service-terms-release.md)に基づく実装後も残っている実環境検証、法務確認、プロダクト判断を管理します。

### 所有する概念

- Web、LINE、直接APIを横断するPreview検証と完了条件
- 規約改定の告知方法に残るプロダクト判断
- 未同意時のデータ保持・削除導線に残る法務・プロダクト判断
- 利用規約とプライバシーポリシーの公開前レビュー

### 所有しない概念

- 規約の版管理、同意記録、同意画面、同意前後の利用可能範囲
- 新しいversionの追加、本文hash検証、公開、forward-onlyな訂正手順
- 利用規約とプライバシーポリシーの本文
- Account削除、本人データ取得、同意取消の新しい方針

規約と同意体験は[サービス利用規約・同意体験設計](../product/service-terms-consent-experience.md)、公開手順は[サービス利用規約の公開運用](service-terms-release.md)、公開サイト全体に残る作業は[サービス紹介サイト残タスク](service-site-remaining-tasks.md)を正とします。

## 2. 現在の残タスク

### 2.1 Previewで3経路の同じversionへの収束を確認する

法務・プロダクト責任者が本文と`requiresReacceptance`を確定した新versionをPreviewへ反映したとき、次を実環境で確認します。この検証のためだけに仮の公開versionや本文を追加しません。

- 新規Accountでは、Webの主機能より先に初回同意画面が表示される
- 重要改定前の同意だけを持つ既存Accountでは、Webで再同意を求める
- 現行versionへ同意済みのAccountでは、同意画面を再表示せず利用を継続できる
- 未同意のLINEメッセージは本人コンテンツを保存せず、規約画面のLIFFリンクを案内する
- LINEの案内先とWebが取得する規約、および直接APIが同意として受理するversionと本文hashが一致する
- 未同意の直接APIは、同意前に許可された操作を除いて`428 terms_not_accepted`を返す

完了条件は、初回同意、改定再同意、同意済み継続を同じPreview releaseで確認し、Account ID、LINE user ID、session、token、規約本文に含まれない個人情報をIssueやPRの証跡へ残さず、結果と確認日時を記録できることです。

### 2.2 改定の告知方法を決定する

重要改定と軽微改定のそれぞれについて、告知する経路、時期、表示期間、適用日前の扱いをプロダクト責任者と法務担当者が決定します。決定前にWeb通知、LINE push、メールなど特定の経路を実装しません。

完了条件は、決定内容が適切なSSoTへ反映され、公開手順、利用者向け表示、実際の配信設定が一致することです。

### 2.3 未同意時のデータ保持・保護操作を決定する

同意しない利用者について、既存データの保持期間、Account削除、本人データ取得・削除、同意取消を提供するか、提供する場合にどの本人確認と導線を使うかを法務・プロダクト責任者が決定します。現在の許可・拒否範囲は[同意体験設計](../product/service-terms-consent-experience.md#6-同意前の利用範囲)を維持し、この残タスク文書だけで例外を追加しません。

完了条件は、利用者向け文言、APIの許可・拒否matrix、自動テスト、保存・削除の実処理が、承認された方針と一致することです。

### 2.4 公開前の法務・運用情報を確定する

- 実際の事業形態と提供機能に照らして、利用規約とプライバシーポリシーの法務レビューを完了する
- [サービス紹介サイト設計](../product/service-site-design.md)で確定した運営者と問い合わせ窓口、取り扱う個人情報、利用目的、外部送信先、保存・削除方法を承認済みの正本へ反映する
- [サブスクリプション・料金プラン設計](../product/subscription-plan-design.md)の年齢・契約条件と[Account復旧設計](../architecture/account-recovery-design.md)の復旧不能時の境界を含む重要改定versionを追加して再同意を求める
- [特定商取引法に基づく表記の設計](../product/service-site-design.md#74-特定商取引法に基づく表記)で確定した開示手順を公開・検証する
- 問い合わせ窓口とデータ関連請求の運用が実際に機能することを確認する

完了条件は、承認済みの本文が公開中の正本と一致し、記載した窓口とデータ取扱いを実運用で再現できることです。

## 3. 更新ルール

- 未完了の作業だけをこの文書へ残し、完了した項目は削除する
- 実装を始めた項目は個別のIssueまたはPRへ移し、この文書にはリンクと未完了の確認事項だけを残す
- 同意体験または公開手順を変更する場合は、先に対応するSSoTを更新する
- 法務・プロダクト判断を推測で埋めず、決定者と根拠を追跡できる形で反映する
- すべての項目が完了したら、この文書とドキュメントマップのリンクを同じ変更で削除する
