# Brain Item残タスク

## 1. 目的

この文書は、診断と日記からBrain Itemを生成し、Vectorizeを経由して通常チャットで利用する基本機能の提供後に残っている検証、品質改善、延期中の機能を管理します。

### 所有する概念

- Brain Item生成・意味的重複判定・Vectorize利用に残っている検証項目
- 品質評価を継続できる状態にするための改善
- 方針上いったん延期する機能と、着手時の完了条件

### 所有しない概念

- Brain Itemの分類、共通属性、生成規則
- Source Recordの訂正、削除、取り消し、撤回がBrain Itemへ及ぼす影響
- Evidence、反証、改訂の関係
- 日記チャットの会話、配送、Queue、AccountDataの実装設計
- 共通のデプロイ手順と運用ログ方針

生成規則と実装済み範囲は[Brain Item生成設計](../domain/brain/brain-item-generation-design.md)、Source Record操作の波及は[Source Recordのライフサイクル設計](../domain/source/source-record-lifecycle-design.md)、Evidenceと改訂は[根拠・反証・改訂のエッジ設計](../domain/brain/evidence-edge-design.md)、日記チャットの実行経路は[日記チャット実装設計](../architecture/diary-chat-implementation-design.md)、ログへ記録できる情報は[アプリケーション運用ログ方針](operational-logging.md)を正とします。

## 2. 次に行うタスク

### 2.1 PreviewでBrain Item生成から通常チャット利用まで確認する

- 日記から許可された各分類のBrain Itemを生成し、Evidenceと時点情報が保存されることを確認する
- 表現が異なる同一命題では既存ItemへEvidenceだけが追加され、別の命題や時点が異なる情報は統合されないことを確認する
- 同じcheckpoint内の同一命題が1件へまとまり、複数の根拠を保持することを確認する
- Vectorize同期後、関連する通常チャットで再認可済みItemがContext Packageへ入り、開発用表示と監査記録が実際の利用結果に一致することを確認する
- AI、Vectorize、Queueの一時失敗後も、重複したItemやEvidenceを作らず再試行できることを確認する

完了条件は、個人情報、日記本文、Brain Item本文、Account IDをログやチケットへ転記せずに、生成、意味的統合、Vectorize同期、検索、通常チャット利用までの一連の成功と再試行時の冪等性をPreviewで確認できることです。

### 2.2 意味的重複判定の評価datasetと更新基準を整備する

- 同一命題、関連しているだけの命題、具体性・強さ・対象・時点が異なる命題を含む匿名化した評価例を用意する
- 6分類ごとに、統合すべき例と統合してはいけない例を含める
- 既存Itemとの比較と、同じcheckpoint内の新規候補同士の比較を評価する
- promptまたはモデル変更時に、誤統合と統合漏れを同じdatasetで比較できるようにする
- 数値の誤統合率は合格条件にせず、同じdatasetによる変更前後の結果をサービス責任者が確認してprompt versionの更新を承認する

完了条件は、意味的重複判定の変更前後を再現可能な入力で比較でき、少なくとも誤統合を自動検出でき、サービス責任者の承認を記録できることです。実際の日記本文をdatasetへ転記せず、作成した評価例または十分に匿名化した例だけを使用します。

## 3. 延期中のタスク

### 3.1 本人の否定・修正・改訂を反映する

この項目は当面実装しません。着手する場合は、本人操作と対象Itemの対応づけ、否定による無効化、修正文からの新Item作成、Revision、通常検索からの除外、Vectorize削除を一つのライフサイクルとして扱います。

完了条件は、対象を一意に解決できない操作でItemを変更せず、AccountDataの状態変更とVectorizeへの反映が一時失敗や再配送を含めて収束することです。操作と状態遷移の規則を変更する場合は、先に関連するSSoTを更新します。

### 3.2 本人が明言していない内容のAI推定を扱う

この項目は当面実装しません。現在の日記変換は本人が明言した内容だけを保存対象とし、単発の出来事から動機、性格、安定した行動傾向を推定しません。

完了条件は、推定であることを本人の明言と区別し、根拠、Confidence、本人への提示と訂正方法、通常チャットでの利用制約を設計したうえで、推定を本人の事実として扱わないことです。

### 3.3 Accountごとのtimezoneで相対日付を解決する

この項目は海外時間帯を扱う段階まで延期します。現在は設計どおり`Asia/Tokyo`を既定として使用します。

完了条件は、Accountのtimezoneの取得元と変更時の扱いを定め、同じ原文とSource Record受信時点から時点情報、Vectorize登録文、検索queryを一貫して生成できることです。既存Itemの時点情報を移行または再解釈するかも着手時に決めます。

### 3.4 Confidenceと分類固有attributesを具体化する

この項目は、算出方法と利用場面を決める段階まで延期します。Confidenceの具体的な算出方法、閾値、表示タイミングと、分類ごとのattributes schemaを一緒に決めず、対応するSSoTの責務に沿って分けて設計します。

完了条件は、Evidenceの増減、本人の明言とAI推定、Source Recordの削除・撤回を安全側に扱える算出・再計算規則が決まり、保存値と通常チャットでの利用判定を再現できることです。

### 3.5 反証候補と矛盾するItemの扱いを決める

この項目は当面実装しません。反証候補を自動的にEvidence edgeへする条件と、矛盾するBrain Itemを自動統合せず本人へ提示する方法を着手時に設計します。

完了条件は、関連しているだけの発言を反証として確定せず、矛盾するItemを一方的に上書きせず、本人が根拠と対象を確認して扱いを選べることです。

## 4. 更新ルール

- 未完了の検証と延期中の項目だけをこの文書へ残し、完了した項目は削除する
- 実装を始めた項目は個別のIssueまたはPRへ移し、この文書にはリンクと未完了の確認事項だけを残す
- 生成規則、ライフサイクル、Evidence、実行経路を変更する場合は、先に対応するSSoTを更新する
- 延期方針を変更した場合は、着手前にこの文書の区分を更新する
- すべての項目が完了したら、この文書とドキュメントマップのリンクを同じ変更で削除する
