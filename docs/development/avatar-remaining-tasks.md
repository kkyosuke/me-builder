# アバター設定残タスク

## 1. 目的

この文書は、[アバター設定体験設計](../product/avatar-experience.md)と[プロフィールAPI契約](profile-api.md)に基づくアバター設定について、基本機能の提供後に残っている自動化・運用改善を管理します。

### 所有する概念

- アバター設定で実ブラウザE2Eにより自動化する回帰シナリオとLIFF実端末確認
- Private R2に残り得る孤立objectを安全に検出・整理する運用改善
- 各改善を完了とする条件

### 所有しない概念

- アバターの表示優先順位、画像選択、プレビュー、保存、削除の利用体験
- プロフィールAPI、共有D1、Private R2の保存契約
- 共通のデプロイ手順と運用ログ方針
- 利用者による切り抜き位置、回転、拡大率の編集

利用体験は[アバター設定体験設計](../product/avatar-experience.md)、HTTP APIと保存時の整合性は[プロフィールAPI契約](profile-api.md)、ログへ記録できる情報は[アプリケーション運用ログ方針](operational-logging.md)を正とします。

## 2. 現在の残タスク

### 2.1 実ブラウザE2EとLIFF実端末確認を追加する

CIで実行する実ブラウザE2Eでは、LIFF初期化が遅延する条件とプロフィールAPIを制御し、少なくとも次の回帰シナリオを確認します。利用するE2Eフレームワークはこの文書では固定しません。

- LIFF初期化の完了後にプロフィール画面を開き、初期化が複数回競合しない
- アプリで設定した画像がない場合はLINEプロフィール画像を表示する
- 画像を選択してもモーダルの高さと主要操作の位置が変わらず、同じ画像領域がプレビューへ切り替わる
- 保存成功後は追加のプロフィール取得を行わず、右上、プロフィール、モーダルへ同じ画像を反映する
- 画面を再読み込みまたは開き直したとき、プロフィール取得の完了前にLINE画像へ一瞬切り替わらず、保存画像を表示する
- 保存失敗時は現在画像と選択中画像を維持して再試行できる
- アプリの画像を削除すると、LINEプロフィール画像またはプレースホルダーへ戻る

モックしたブラウザE2EだけではLINEアプリ内WebView固有の挙動を保証できません。Previewへ反映した後は、LINE内からLIFFを開き直し、保存画像の復元と画面遷移を実端末でも確認します。実端末確認では本人の実画像、Account ID、LINE user IDを動画、ログ、チケットへ残しません。

完了条件は、初期化順序、画像選択、保存、復元、削除の回帰をCIで検出でき、PreviewのLINEアプリ内でも同じ一連の操作が成功することです。

### 2.2 Private R2の孤立object清掃をPreviewで有効化する

プロフィール保存では、共有D1の更新後に以前のR2 objectを削除できなかった場合や、D1更新失敗後に現在参照中か確認できなかった場合に、安全のためobjectを残します。この結果として生じ得る孤立objectを整理する定期処理は実装済みです。次の実環境確認を終えてから実削除を有効にします。

- Previewの`dry-run`で対象件数だけが出力され、Account ID、LINE user ID、R2 object key、画像bytesがログへ出ないことを確認する
- 保存・削除と同時に実行し、24時間以内のobjectと共有D1が参照中のobjectが候補へ入らないことを確認する
- `AVATAR_CLEANUP_MODE=delete`へ切り替え、参照確認またはR2削除の一部失敗後も次回実行で収束することを確認する
- Previewでの確認後にProductionの実削除を有効にし、初回実行の件数と失敗件数だけを記録する

完了条件は、現在参照中または保存途中のobjectを削除せず、猶予期間を過ぎた未参照objectだけを再試行可能な方法で整理できることです。並行する保存・削除と、D1・R2の一時失敗を含むテストでこの境界を確認します。

## 3. 更新ルール

- 未完了の改善だけをこの文書へ残し、完了した項目は削除する
- 実装を始めた項目は個別のIssueまたはPRへ移し、この文書にはリンクと未完了の確認事項だけを残す
- 利用体験またはAPI契約を変更する場合は、先に対応するSSoTを更新する
- すべての項目が完了したら、この文書とドキュメントマップのリンクを同じ変更で削除する
