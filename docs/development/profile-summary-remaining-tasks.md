# わたしのまとめ残タスク

## 1. 目的

この文書は、[わたしのまとめ仕様](../product/profile-summary-experience.md)に基づく「わたしのまとめ」について、完了していない実装と実環境検証、その検証で見つかった改善作業を管理します。

### 所有する概念

- 「わたしのまとめ」に残っている検証項目
- 設計済みだが未実装の項目
- 各検証を完了とする条件
- 検証で問題が見つかった場合の追跡先

### 所有しない概念

- 画面の表示内容、版切り替え、再生成条件などの利用体験
- AI生成、AccountData、Queue、APIの設計
- 共通のデプロイ手順と運用ログ方針

利用体験と生成処理の振る舞いは[わたしのまとめ仕様](../product/profile-summary-experience.md)、デプロイ方法は[開発運用ルール](../../.agents/rules/development.md)、ログへ記録できる情報は[アプリケーション運用ログ方針](operational-logging.md)を正とします。

## 2. 現在の残タスク

### 2.1 セルフケアとAI相談への導線を接続する

- 本人が確認したセルフケア情報を短く表示する
- 「詳しく見る」と「AIに聞く」から、それぞれ対応する画面へ移動できるようにする
- 診断結果だけからストレスの原因や対処法を補わない

完了条件は、[ストレスの手がかりとAIセルフケア相談体験設計](../product/self-care-ai-consultation-experience.md)で定義された情報と安全上の切り替えを再利用し、「わたしのまとめ」側へ別の判定規則を作らないことです。

### 2.2 Previewで実際のAI生成を通しで確認する

- 診断と日記がある本人Accountから生成を要求する
- Web、API、Profile Summary Queue、Worker、Gemini、AccountDataを通って新しい版が保存されることを確認する
- 画面が生成中を表示し、完了後に新しい最新版へ更新されることを確認する
- 日記由来のBrain Itemだけでなく、日記のuser message本文にしかない情報も生成結果へ反映できることを確認する
- 最新版と過去版を切り替えても、それぞれの版の本文と生成情報が変わらないことを確認する

完了条件は、個人情報や日記本文をログやチケットへ転記せずに、上記の一連の成功を確認できることです。

### 2.3 生成内容の品質を確認する

- 診断だけ、日記だけ、診断と日記の両方がある入力をそれぞれ確認する
- 入力にない人物像、健康状態、将来の行動を断定しないことを確認する
- 日記本文を長く引用せず、複数の根拠を重複の少ない最大3件のinsightへまとめることを確認する
- 診断と日記の両方を使ったinsightで、画面の根拠種別と件数が生成入力と一致することを確認する

完了条件は、修正が必要な出力例を匿名化して追跡でき、問題がない場合は使用した入力条件と確認結果だけを記録できることです。プロンプトやschemaの変更が必要になった場合は、この文書へ詳細設計を追加せず、個別のIssueまたはPRで扱います。

数値の合格閾値は設けません。診断だけ、日記だけ、診断と日記の両方があるPreviewの実出力をサービス責任者が確認し、承認した記録を公開条件とします。

### 2.4 生成失敗と再試行を実環境相当で確認する

- Geminiの一時エラーとschema不適合でQueueが再試行されることを確認する
- 最終試行まで失敗した場合に生成要求が`failed`となることを確認する
- 失敗中も最後に成功した版を閲覧でき、画面から再試行できることを確認する
- Queueの再配送によって同じ生成要求から複数の版が作られないことを確認する

完了条件は、一時失敗、最終失敗、再試行成功の各結果を、機微情報を含まない運用ログと保存状態から判定できることです。

### 2.5 PreviewとProductionの構成を確認する

- Profile Summary QueueとDLQ、AccountData binding、Geminiの認証情報とモデル設定が各環境へ配布されていることを確認する
- Previewでは入力変更や7日経過がなくても再生成でき、Productionでは入力・形式の変更と7日経過を両方求める通常の再生成判定が維持されることを確認する
- 生成フローの成功、破棄、再試行、最終失敗を運用ログから区別できることを確認する

完了条件は、環境固有のSecret値を文書へ記載せずに、必要なbindingと設定の有無を確認できることです。

## 3. 更新ルール

- 未完了の検証だけをこの文書へ残し、完了した項目は削除する
- 検証で実装変更が必要になった場合はIssueまたはPRへ移し、この文書にはリンクと未完了の確認事項だけを残す
- 利用体験や生成規則を変更する場合は、先に[わたしのまとめ仕様](../product/profile-summary-experience.md)を更新する
- すべての項目が完了したら、この文書とドキュメントマップのリンクを同じ変更で削除する
