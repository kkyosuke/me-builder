# アバター設定体験設計

## 1. この文書の目的

この文書は、本人が自分の画像をアップロードし、AIで人物が写っていることを確認した後、生成した複数候補から1つを選び、自分のアバターとして設定する体験を定義します。アバターの表示場所、アップロード、人物判定、AI生成の待ち方、候補選択、差し替え・削除、画面状態、プライバシー上の説明、および機能の完了条件を所有します。

プロフィールの入口と設定項目のまとまりは[プロフィール設定体験設計](profile-settings-experience.md)、全体の画面接続は[全体画面遷移設計](screen-navigation.md)、Account所有データの分離は[Accountデータ分離設計](../architecture/account-data-isolation.md)、R2・Queues・Queue Workerの役割は[インフラ・システム構成](../architecture/infrastructure-architecture.md)を正とします。

この文書は、画像生成モデルや事業者の選定、具体的なプロンプト、API・イベント・データベースのスキーマ、課金プラン、他ユーザーへの公開、MCPでの提供を所有しません。

## 2. 結論

- 共通ヘッダー右上から「プロフィール」を開き、そのアバター自体を入口として設定モーダルを開けるようにする
- 未設定時は共通のプレースホルダーを表示し、LINEのプロフィール画像を本人の操作なく取り込まない
- アップロード後はAIで人物が写っているかを自動判定し、人物を確認できない場合は自分が写っている画像の選び直しを求める
- モーダルで画像を選んでプレビューを確認し、送信を確定すると人物判定とAI変換へ進める。アップロード画像そのものはアバターに設定しない
- AI生成は時間の読めない外部処理なので、Cloudflare Queuesを使う永続的な非同期ジョブにする
- 生成中に画面を離れたりブラウザを閉じたりしても処理を続け、再訪時に同じ状態と候補を復元する
- 初期提供では最大4件の候補を作り、1件ずつ比較して明示的に「このアバターに設定」する
- アップロードや生成を開始しただけでは現在のアバターを変更せず、選択の確定時にだけ一括で差し替える
- AI生成の完了を知らせるLINE Pushは初期提供に含めず、Webの「プロフィール」に「候補ができました」と表示する

AI生成を同期レスポンスに含めると、タイムアウト、再送による二重生成、画面を閉じたときの結果喪失が起きやすくなります。受付と実行を分け、生成状況そのものを保存することで、待ち時間を利用者の画面滞在時間から切り離します。

## 3. 提供範囲

### 3.1 初期提供に含めるもの

- 端末から自分が写っている写真を1件アップロードする
- 正方形サムネイルとして使う範囲を確認・調整する
- AIで人物が写っているかを判定し、人物を確認できない場合は画像の選び直しを案内する
- アップロード画像を参照画像として、プロダクトが用意した画風でAI候補を生成する
- 生成状況を確認し、完成した候補を拡大・比較する
- 生成候補へ現在のアバターを差し替える
- 現在のアバターを削除してプレースホルダーへ戻す

初期提供では自由記述の生成プロンプトを設けません。本人が意図せず不適切な画像を作ること、生成結果のばらつき、プロンプト保存に伴う新たな個人情報を増やさず、アバターを選ぶ目的に集中するためです。

### 3.2 表示場所

現在のアバターは次へ表示します。

- 共通ヘッダー右上のプロフィール入口
- 「プロフィール」のアバター項目
- 「わたしの傾向」のヘッダー
- 主ナビゲーションの「わたし」アイコン
- 「アバター設定」の現在値プレビュー

主ナビゲーションでは画像の有無にかかわらず「わたし」というラベルと選択状態を残します。画像だけをナビゲーションの意味や現在位置の手がかりにしません。

初期提供のアバターは本人がログインしたWeb内だけで使います。LINE公式アカウントのプロフィール、管理者画面、他ユーザー向け画面、MCPのプロフィール出力へは連携しません。

## 4. 画面構成

```text
┌──────────────────────────────┐
│ プロフィール                 │
├──────────────────────────────┤
│ アバター                     │
│ (現在の画像・生成状態)       │
│                              │
│ ┌ アバター画像を選ぶ ─────┐ │
│ │ [選んだ画像のプレビュー] │ │
│ │ [この画像で候補を作る]   │ │
│ └────────────────────────┘ │
│                              │
│ ┌ 候補から選ぶ ──────────┐ │
│ │ [候補1] [候補2]          │ │
│ │ [このアバターに設定]     │ │
│ └────────────────────────┘ │
└──────────────────────────────┘
```

状態に応じて不要な領域は表示しません。未アップロード時に空の候補枠を並べたり、生成中に確定操作を有効にしたりしません。

### 4.1 入口と現在値

共通ヘッダー右上のプロフィール操作から「プロフィール」を開き、アバター画像とその状態をまとめた操作から設定モーダルを開きます。未設定時も同じ位置にプレースホルダーを表示し、機能を発見できるようにします。入口とプロフィール画面の振る舞いは[プロフィール設定体験設計](profile-settings-experience.md)を正とします。

人物判定・生成中はアバター上に処理中の表示を重ね、補助文を「アバターを生成中」とします。この間は新しい画像の送信を受け付けず、モーダルを開かなくても進行中と分かるようにします。候補完成後は「候補ができました」へ切り替え、アバターの操作から候補選択モーダルを開きます。

### 4.2 アップロードと自動生成

画像送信モーダルでは、ファイル選択後、送信前に次を確認できます。

- 円形表示から内容が切れない正方形の表示範囲
- 対象の画像と、選択し直す操作
- 人物確認と候補生成をまとめた処理中、人物を確認できない状態

「この画像で候補を作る」を押すまで画像は送信しません。送信受付後はモーダルを閉じ、人物判定を自動で開始して、画像に人物が写っているかだけを確認します。写っている人物が利用者本人かを認証するものではなく、性格、年齢、健康状態などの属性を推定しません。人物を確認できない場合は現在のアバターを維持し、プロフィールのアバター状態と再度開いたモーダルで「ご自身の顔や上半身が見やすい画像を選んでください」と再アップロードを案内します。

ファイル選択の直前に、外部の画像生成サービスへ送信すること、処理に時間がかかること、候補が自動設定されないこと、画像を使う権利と写っている人の同意が必要なことを常に説明します。別の同意チェックボックスは設けません。人物を確認できた場合は、送信後の同じ非同期ジョブの中で候補生成へ自動で進みます。

### 4.3 候補の比較と設定

候補一覧はプロフィール上へ展開せず、候補完成時にアバターを押して開くモーダルへ表示します。1件を選択状態にし、候補カード自体のタップで現在のアバターを変更せず、「このアバターに設定」で確定します。

設定が成功したら、現在値を即座に更新して「プロフィール」へ戻れるようにします。失敗した場合は候補の選択を維持し、同じ操作を再試行できます。

本番では現在のアバターを設定、差し替え、削除した時点をプロフィール変更として記録し、次の変更まで7日間空けます。初回設定は制限せず、previewとlocalでは動作確認を妨げないよう変更間隔を設けません。制限中に候補を選択した場合は候補を維持し、次に変更できる日時を表示します。

## 5. 基本フロー

```mermaid
flowchart TD
    P[プロフィールのアバター] --> S[画像送信モーダル]
    S --> U[画像を選択してプレビュー]
    U --> V{形式・容量・内容を確認}
    V -->|利用不可| UE[理由と選び直し]
    UE --> U
    V -->|利用可| C[表示を確認して送信]
    C --> D{AIで人物を確認}
    D -->|人物を確認できない| UE
    D -->|人物を確認できた| J[候補生成を自動で受け付ける]
    J --> W[モーダルを閉じて生成中をアバターへ表示]
    W --> R{生成結果}
    R -->|一部以上完成| G[アバターから候補選択モーダルを開く]
    R -->|すべて失敗| F[失敗理由と画像の選び直し]
    F --> U
    G --> E[候補を1件選択]
    E --> A[現在のアバターへ設定]
    A --> P
```

## 6. AI生成の非同期設計

### 6.1 利用者から見える待ち方

画像を選んだ後は、実測できない進捗率や断定的な完了時刻を表示しません。人物判定中と生成中をまとめて「アバター候補を作っています」と示し、補助文で現在の処理を伝えます。最終的には「候補ができました」または人物なし・生成失敗のエラーへ収束させ、「数分かかることがあります。この画面を閉じても生成は続きます」と伝えます。

画面を開いている間だけ低頻度で状態を再取得します。別画面へ移動した後はブラウザ内で処理を継続させる必要はなく、再び「プロフィール」または「アバター設定」を開いたときにサーバー上の最新状態を取得します。

人物確認・生成中は「プロフィール」のアバター項目にも「候補を生成中」と表示し、アバター設定を閉じても進行中であることを確認できるようにします。生成完了時は同じ場所を「アバター候補ができました」という控えめな案内へ切り替えます。初期提供では、次の理由によりLINE PushとブラウザPushを使いません。

- アバター生成は緊急性がなく、チャットや診断通知へ新しい通知種別を混ぜる必要がない
- 通知の同意、配送失敗、通知からの復帰先を別途設計する必要がある
- 再訪時の状態復元だけで結果を失わずに済む

### 6.2 システムの流れ

```mermaid
sequenceDiagram
    participant U as 利用者
    participant W as Web UI
    participant A as API Server
    participant D as AccountData
    participant Q as Cloudflare Queues
    participant K as Queue Worker
    participant I as 画像生成サービス
    participant R as Private R2

    U->>W: 説明を確認して画像を選ぶ
    W->>A: 認証済みのアップロード
    A->>R: 正規化した参照画像を保存
    A->>D: 受付状態・未投入マーカー・再投入時刻を保存
    A->>Q: 同じジョブIDを投入
    alt Queue投入に成功
        A->>D: 未投入マーカーを解消
    else Queue投入に失敗
        D->>Q: alarmから同じジョブIDを再投入
    end
    A-->>W: APIが応答可能なら受付済み
    W-->>U: 画面を離れてよいと表示
    Q->>K: 人物判定ジョブを配送
    K->>D: 人物判定の実行権を確認
    K->>R: 参照画像を取得
    K->>I: 人物の有無を判定
    alt 人物を確認できた
        K->>D: 生成受付へ自動遷移
        K->>Q: 同じジョブIDの生成を投入
        Q->>K: 生成ジョブを配送
        K->>D: 生成の実行権を確認
        K->>I: 候補生成
        I-->>K: 候補または失敗
        K->>R: 検査済み候補を保存
        K->>D: 完了状態と候補参照を保存
    else 人物を確認できない
        K->>D: 人物なしで完了
    end
    W->>A: 再訪時または表示中に状態取得
    A->>D: 本人の生成状態を取得
    A-->>W: 状態と表示可能な候補
```

外部AIの応答待ちの間にAccountDataを占有しません。実行前の短い状態更新、外部呼び出し、結果の短い保存へ処理を分けます。

受付状態と未投入マーカー、再投入時刻はAccountDataの同じ更新で保存します。Queue投入とAccountData更新は単一transactionにできないため、「AccountDataへ受付だけ残った」「Queueへ届いたが成功応答前にAPIが停止した」のどちらも正常な中間状態として扱います。AccountDataのalarmは未投入マーカーを再確認し、同じジョブIDをQueueへ再投入します。Workerが既に開始済みまたは完了済みなら、再配送された同じジョブを実行しません。

受付済みジョブは、最終的に生成開始または再投入期限超過による失敗のいずれかへ進めます。Queue投入障害を理由に`accepted`へ無期限に残しません。

### 6.3 重複と再試行

- 1 Accountにつき同時に実行できる生成は1件とし、ファイル選択の再送や通信再送で生成費用を重複させない
- 同じ受付を再送した場合は、進行中の生成状態を返し、未投入なら同じジョブIDの再投入を促す。新しい生成は増やさない
- 生成受付前に、サーバー側でAccount単位の一定期間内の生成回数と、環境全体の利用量・予算上限を確認する。クライアント表示や同時実行数だけを費用制御にしない
- Account上限へ達した場合は次に利用できる時期を案内し、全体上限へ達した場合は一時的に利用できないことを案内する。どちらの場合も現在のアバターを維持し、別画像の選択や後日の再試行は利用できる
- 同じジョブの再送とシステム都合の再試行は新しい生成回数として数えない
- 一時的な外部障害はQueue Workerが上限付きで再試行し、同じ候補を重複登録しない
- 一部の候補だけが正常なら、完成した候補を表示し、全件そろうまで無期限に待たせない
- 全候補が失敗した場合だけ生成失敗とし、現在のアバターとアップロード確認状態を維持する
- 新しい候補が完成しても、生成開始後に本人が別のアバターを設定していれば自動で上書きしない

## 7. 状態とライフサイクル

### 7.1 生成状態

```mermaid
stateDiagram-v2
    [*] --> checking: アップロード受付
    checking --> not_person: 人物を確認できない
    checking --> accepted: 人物確認後に自動受付
    checking --> failed: 人物判定失敗
    accepted --> generating: Workerが開始
    accepted --> failed: 再投入期限を超過
    generating --> ready: 1件以上の候補が完成
    generating --> failed: 候補が0件
    ready --> selected: 候補を設定
    ready --> expired: 保持期限を経過
    not_person --> [*]
    selected --> [*]
    expired --> [*]
```

`ready`は候補が利用可能であることを表し、現在のアバターに採用済みであることを表しません。現在値の更新は`selected`への明示操作でだけ行います。

### 7.2 画像の保持

- 端末から受け取ったファイルは、向き、色空間、画像形式、寸法をサーバー側で正規化し、位置情報を含む不要なメタデータを除去する
- AI生成に使う正規化済み参照画像はprivate R2へ置き、最後の生成が終了してから最大24時間の削除猶予後に削除する
- 未選択の生成候補は生成完了から7日間保持し、期限と削除予定を候補画面に表示する
- 選択された画像は現在のアバターとして、差し替えまたは削除まで保持する
- 差し替え前のアバターと期限切れの候補は、参照されなくなったことを確認して削除対象にする
- 候補は参照画像の削除後も7日間確認・設定できる。新しい候補を作る場合は、画像を改めて選択してアップロードする

削除が失敗した場合は利用者の操作を成功と見せて参照だけ残すのではなく、再試行可能な削除状態として管理します。画面からは選択できないようにし、運用ログには画像本文、署名付きURL、Accountの外部識別子を残しません。

## 8. 責務境界

アバターは「その人らしさを推定した情報」ではなく、本人が選ぶAccountの表示設定です。アップロード画像や生成候補からBrain Itemを作らず、画像認識は人物の有無だけに限定します。人物の本人性、性格、年齢、属性、健康状態などを推定しません。

| 領域 | 責務 |
| --- | --- |
| Web UI | ファイル選択、表示範囲の確認、人物判定状態の表示、候補比較、本人の確定操作 |
| API Server | Accountの本人確認、アップロード受付、ファイル検査、人物判定の依頼、AccountDataへの操作依頼、短時間での受付応答 |
| AccountData | 現在のアバター、本人が所有する画像参照、生成状態、選択・中止・削除の一貫性 |
| Private R2 | 正規化済み参照画像、生成候補、現在のアバター画像のバイナリ |
| Cloudflare Queues | 受付済み生成ジョブの非同期配送 |
| Queue Worker | 重複実行の防止、外部画像生成、候補検査、再試行、結果保存 |
| 画像生成サービス | 同意された参照画像から候補画像を生成する外部処理 |
| 人物判定サービス | アップロード画像に人物が写っているかだけを判定する外部処理 |

現在のアバター参照と生成状態はAccount所有データなので、認証結果から選んだAccountDataへ保存します。クライアントが指定したAccount IDやR2オブジェクトキーを認可根拠にしません。物理的なテーブル、RPC、Queue messageの形は実装設計まで延期します。

## 9. プライバシーと安全性

- 画像はprivate R2へ保存し、公開bucket URLを現在値や候補の恒久URLとして返さない
- 表示は認証済みAccountを確認する経路、または短時間だけ有効な表示権限を通す
- ファイル名、EXIF、端末内のパス、署名付きURL、画像のbase64をログへ出力しない
- 拡張子だけを信頼せず、実データの形式、容量、寸法、デコード可否をサーバー側で検査する
- SVGなど能動的な内容を持ち得る形式は受け付けず、安全なラスター形式へ限定する
- 人物判定は人物の有無だけを返し、本人認証や顔照合、属性・感情・健康状態の推定に利用しない
- 人物を確認できない結果は再アップロードの案内にだけ使い、Brain Itemや本人の評価として保存しない
- AIへ送る前に、利用者が画像を使う権利を持つこと、写っている人の同意を得ていること、外部の画像生成サービスへ送られることを説明する
- 画像生成事業者の学習利用、保持期間、処理地域が要件を満たすことを、モデル選定時の必須条件にする
- 生成候補は安全性検査と画像デコード検査を通過したものだけ表示する
- AI生成であることは候補選択中に表示する。ただし本人が設定した後の小さなアバターへ恒常的なAIラベルは付けない
- AI生成の失敗や安全性判定から、理由以上のセンシティブな推測を利用者へ返さない

## 10. 画面状態と回復

| 状態 | 表示と回復 |
| --- | --- |
| アバター未設定 | プレースホルダーと「画像をアップロード」 |
| 設定済み | 現在値、変更、削除 |
| ファイル不正 | 容量・形式・破損など本人が直せる理由と選び直し |
| アップロード中 | 対象画像を示した待機表示。重複送信を無効化 |
| アップロード失敗 | 現在値を維持し、同じ画像の再試行または選び直し |
| 人物判定中 | 「アバター候補を作っています」と人物確認中であることを表示 |
| 人物を確認できない | 現在値を維持し、自分の顔や上半身が見やすい画像の選び直しを案内 |
| 人物確認済み | 追加操作を求めず、自動で生成受付へ進む間の処理中表示 |
| 生成受付済み | 候補を生成中であることと、画面を離れてよい旨 |
| 生成中 | 不確かな割合を出さず、状態と画面を閉じても継続する旨を表示 |
| プロフィール表示中に処理中 | アバター項目に「候補を生成中」と表示し、状態取得を続ける |
| Account生成上限 | 次に生成できる時期と、別画像を選べる操作 |
| 全体利用上限 | 一時的にAI生成を利用できない説明と、別画像を選べる操作 |
| 一部候補が完成 | 完成分を選択可能にし、一部失敗を短く説明 |
| 全候補が失敗 | 現在値を維持し、別画像の選択 |
| 候補あり | 候補、候補の保持期限、選択、新しく作る場合の画像再アップロード |
| 候補期限切れ | 期限切れを説明し、再アップロードへ案内 |
| 設定失敗 | 選択候補を維持して再試行 |
| 本番の変更間隔内 | 現在値と選択候補を維持し、次に変更できる日時を表示 |
| 削除失敗 | 現在値を維持して再試行 |
| 通信失敗 | 最後に確認できた現在値を勝手に変更せず、再取得 |

別Accountへ切り替わった場合、以前のAccountの現在値、アップロードプレビュー、生成状況、候補、キャッシュを表示しません。

## 11. アクセシビリティとレスポンシブ表示

- 画像には「現在のアバター」「AI候補1」など、役割と選択状態が分かる代替テキストを付ける
- 候補の選択状態を色や枠線だけで伝えず、テキストまたはアイコンと支援技術向け状態を併用する
- 生成状態の変化はライブリージョンで通知するが、状態取得のたびに同じ文言を読み上げない
- ファイル選択、表示範囲の調整、候補選択、確定、削除をキーボードでも操作できるようにする
- 画像の切り抜き操作には、拡大・縮小と位置を戻せる操作、および操作なしで使える既定の中央配置を用意する
- 小さい画面では候補を2列、大きい画面では内容が過度に拡大しない範囲で並べ、拡大確認を別領域またはダイアログで行う
- 動きの軽減設定では、候補出現や生成中表示に必須でないアニメーションを使わない

## 12. 観測する指標

次のイベントを、画像本文、ファイル名、プロンプト、外部の個人識別子を含めずに集計します。

- アップロード開始・成功・失敗
- 人物判定の開始・確認済み・人物を確認できない結果と処理時間
- AI生成の受付・完了・一部完了・失敗と処理時間
- Account生成上限・全体利用上限で受付しなかった回数
- 受付から最初のQueue投入までの時間、alarmによる再投入回数、受付状態で期限超過した回数
- 生成候補から設定した回数
- 候補を設定せず期限切れになった回数
- 再試行回数と、失敗種別ごとの件数

生成時間は受付から候補利用可能までを測り、画面を開いていた時間とは分けます。これにより、生成自体が遅いのか、利用者が結果へ戻っていないのかを混同しません。

## 13. 実装順序

```mermaid
flowchart LR
    A[1. 表示とプレースホルダー] --> B[2. アップロードと人物判定]
    B --> C[3. 人物確認後の非同期生成]
    C --> D[4. 状態復元と候補比較]
    D --> E[5. 設定・期限削除・運用計測]
```

まずアップロードと人物判定を完成させ、人物を確認できない画像を生成へ進めない縦切りを作ります。その後、人物確認済みの画像だけを対象に、非同期生成、候補比較、設定を接続します。

## 14. 完了条件

- 未設定時にプレースホルダーが表示され、右上のプロフィール入口から設定を開始できる
- 自分の画像をアップロードし、人物の有無をAIで確認できる
- 人物を確認できない場合は現在値を失わず、自分が写っている画像を選び直せる
- 人物を確認できた場合だけAI生成へ進め、アップロード画像そのものは現在値に設定しない
- 利用できない画像では理由を確認し、現在のアバターを失わずに選び直せる
- ファイル選択前に外部送信、画像の権利と写っている人の同意、待ち時間、候補が自動設定されないことを理解でき、プレビュー確認後の送信操作で開始する
- 人物を確認できた画像は追加操作なしで候補生成へ進み、画面は候補選択または人物なし・生成失敗のエラーへ収束する
- 生成受付後すぐに画面を離れられ、再読み込みや再訪後も同じ生成状態へ復帰できる
- APIが受付保存後かQueue投入後に停止しても、同じジョブIDが再投入され、受付済みのまま無期限に残らない
- 再送やQueueの再配送で同一生成が重複せず、1 Accountの生成が別Accountへ表示されない
- Account単位または環境全体の生成上限へ達した場合、AI生成を停止し、現在値を維持したまま再試行時期を確認できる
- 1件以上完成した候補を比較し、明示的な確定操作で現在のアバターに設定できる
- 参照画像の削除後も候補を設定でき、新しい候補の生成には画像の再アップロードを求められる
- 生成・アップロード・設定の失敗時も、それまでの現在のアバターを維持できる
- 期限切れ、差し替え、削除に応じて不要画像が保持方針どおり削除される
- 現在のアバターが共通ヘッダー右上、「プロフィール」、「わたしの傾向」、主ナビゲーションへ一貫して表示される
- マウス、タッチ、キーボード、支援技術で主要操作と状態確認ができる

## 15. この設計で決めないこと

- 画像生成モデル、API事業者、具体的なプロンプトと画風
- 受け付ける形式、ファイル容量、画素数の具体的な上限
- API path、request / response、Queue message、AccountData RPCの具体形
- table、column、R2 object key、署名付きURLの具体的な実装
- Account単位の生成回数、全体予算、レート制限、再投入期限の具体値
- AI候補を追加購入する体験
- LINE PushまたはブラウザPushによる完了通知
- アバターの他ユーザーへの公開、共有、MCP提供
- LINEプロフィール画像との同期
- 動画アバター、3Dアバター、着せ替えパーツ

これらは、利用状況、費用、採用する画像生成サービスの契約条件を確認してから個別に設計します。
