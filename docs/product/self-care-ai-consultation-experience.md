# ストレスの手がかりとAIセルフケア相談体験設計

## 1. この文書の目的

この文書は、本人が「自分はどんなときに負荷を感じやすく、どんなサインが出て、何をすると整いやすいか」を確認し、現在の状況についてAIへ相談する体験を定義します。表示するセルフケア情報、情報の確かさの区別、AI相談への入口、返答の構成、安全時の切り替え、本人による確認とフィードバックを所有します。

診断を横断したプロフィール画面は[自分の傾向サマリー体験設計](profile-summary-experience.md)、日記チャットの会話原則と記憶を使った助言は[日記チャット体験設計](diary-chat-experience.md)、Brain Itemの分類は[Brain内部情報の分類](../domain/brain/brain-content-taxonomy.md)、AI処理のガードレールは[日記チャット実装設計](../architecture/diary-chat-implementation-design.md)を正とします。

この文書は、医療的な診断、治療、ストレスや症状のスコアリング、AIモデル・プロンプト・API・データベースの具体的な実装、緊急窓口情報の運用方式を所有しません。

## 2. 結論

利用者にとって役立つのは「ストレスを溜めやすい人」という評価ではなく、本人が次の行動を選べる「わたしのセルフケア」です。

```text
負荷がかかりやすい場面
        ↓
早めに気づくサイン
        ↓
自分に合う小さな対処
        ↓
一人で抱えない目安と相談先
```

診断回答だけからストレスの原因を断定しません。診断の傾向はAIが本人へ質問するための手がかりにできても、実際に負荷がかかった出来事や本人の確認がない段階では仮説です。

「わたしの傾向」画面には「わたしのセルフケア」カードと「AIに聞く」操作を追加します。AIは、今の状況を最優先し、本人が確認した過去の情報を根拠として、負担の小さい選択肢を提案します。診断者や治療者として振る舞わず、状態が重い、長引く、または差し迫った危険がある場合はセルフケア提案だけで完結させません。

## 3. 表示すると役立つ情報

### 3.1 負荷がかかりやすい場面

抽象的な性格ではなく、本人が場面を思い出せる粒度で表示します。

- 急な予定変更が続いたとき
- 人へ頼る前に自分で抱え込んだとき
- 相手へ断りたいことを言えなかったとき
- 休む時間を決めないまま作業を続けたとき

これらは表示例であり、診断の軸から直接確定しません。「事前計画を重視する」という傾向から「急な変更に必ず弱い」と読み替えず、日記や会話で実際の場面が語られ、本人が確認した場合に表示します。

### 3.2 早めに気づくサイン

本人が過去に話した変化を、次の3種類に分けて表示します。

| 種類 | 表示例 |
| --- | --- |
| こころ | イライラしやすい、気持ちが落ちる、考えがまとまりにくい |
| からだ | 眠りにくい、肩に力が入る、食欲が普段と違う |
| 行動 | 返信を後回しにする、人を避ける、休まず続ける |

一般的なサイン一覧を本人の事実として混ぜません。本人がまだ自分のサインを登録していない場合は、一般的な例であることを示して選択・編集してもらいます。

### 3.3 自分に合いやすい対処

「正しい対処法」の一覧ではなく、本人が試し、役立ったと確認したものを優先します。

- いま5分でできること
- 今日中にできること
- 落ち着いてから予防としてできること
- 誰かへ頼るときの具体的な伝え方

各項目には「以前役立った」「本人が試したいと選んだ」「一般的な案」の区別を表示します。過去に合わなかった方法は「合わなかったこと」として分け、同じ提案を繰り返さないために使います。

### 3.4 一人で抱えないための情報

本人が頼りやすい人・場所と、相談へ切り替えたい本人なりの目安を確認できるようにします。

- 連絡できる信頼できる人
- 利用できる医療機関、相談窓口、職場や学校の支援先
- 不調が続く、生活に支障がある、自分で対処しにくいときは専門家へ相談する案内
- 差し迫った危険があるときの現地の緊急窓口

連絡先や相談先は機微情報として扱い、初期状態では外部共有しません。緊急窓口は固定した古い番号をAIに生成させず、利用地域に応じて運営が確認した情報を表示します。

## 4. 情報の確かさを分ける

同じカード内で、情報の由来を次のように区別します。

| 表示 | 意味 | 通常の助言への利用 |
| --- | --- | --- |
| あなたが話したこと | 本人が日記や会話で明言した | 利用できる |
| あなたが確認した傾向 | 複数の記録から導いた仮説を本人が確認した | 利用できる |
| 回答からの手がかり | 診断パラメータ、または未確認のAI仮説 | 質問のきっかけだけに使う |
| 一般的な案 | 本人固有の根拠を持たないセルフケア情報 | 一般論だと明示して提案できる |

未確認の仮説を「あなたのストレス原因」として主要カードへ表示しません。本人が「近い」「少し違う」「違う」「今は分からない」を選べる確認を挟みます。

本人が否定した内容は、言い換えて再承認を迫らず、通常の助言へ使いません。回答・日記の修正や削除で根拠が無効になった場合は、関連するセルフケア情報も再評価します。

## 5. 「わたしの傾向」画面への追加

```text
┌──────────────────────────────┐
│ わたしのセルフケア           │
│                              │
│ 負荷の手がかり               │
│ 急な変更が重なると消耗しやすい│
│                              │
│ 早めのサイン                 │
│ 返信を後回しにし始める       │
│                              │
│ 合いやすかったこと           │
│ 予定を1つ減らして早めに休む  │
│                              │
│ [詳しく見る]  [AIに聞く]     │
└──────────────────────────────┘
```

カードには、本人が確認した情報だけを最大1件ずつ短く表示します。確認済み情報がない項目をAIで埋めず、「AIと一緒に見つける」または「自分で追加する」と表示します。

「AIに聞く」はセルフケアカード全体と、個別の傾向・手がかりのそれぞれから利用できます。どこから開いたかを会話の文脈として引き継ぎますが、画面上のサマリー文章だけを本人情報の根拠にはしません。

## 6. AIに聞く体験

### 6.1 入口

白紙の入力欄だけで始めず、次の短い入口を用意します。

- 今しんどい。何からすればいい？
- この傾向だと、どんな場面で疲れやすそう？
- 最近の記録から、早めのサインを整理したい
- 自分に合いそうな休み方を一緒に考えたい
- 自由に聞く

2つ目の質問では、AIが診断結果だけから答えを確定せず、「この傾向だけでは決められない」と伝えたうえで、最近実際に消耗した場面を1つ尋ねます。

### 6.2 最初に確認すること

本人が現在つらいと述べている場合は、過去の傾向を説明する前に今の状態を確認します。一度に質問票を埋めさせず、返答に必要なものを1つだけ聞きます。

- いま起きていること
- 共感、整理、具体的な案のどれを求めているか
- 今日すぐできることを探すか、今後の予防を考えるか
- 安全上の懸念があるか

本人が「どうしたらいい」と明確に尋ねた場合、助言してよいかを重ねて確認しません。

### 6.3 AIが参照する順序

1. 今回本人が話した状況と希望
2. 本人が確認した負荷の場面、サイン、役立った・合わなかった対処
3. 本人が確認したBrain Itemと最近のCurrent State
4. 現在有効な診断結果と日記の具体的な出来事
5. 一般的なセルフケア情報

現在の発言と過去の傾向が食い違う場合は、過去を優先しません。診断結果と未確認のAI仮説は質問のきっかけとしてのみ使い、本人に合う助言の根拠として断定しません。

### 6.4 返答の基本形

返答は、本人が今選べる小ささを優先し、原則として次の4点で構成します。

1. 今の状況への短い理解
2. 参照した本人情報と、その確かさ
3. いま試せる1〜3個の小さな選択肢
4. どれが合いそうか、または別の案が必要かの確認

```text
急な予定変更が重なって、頭を切り替え続けるのに疲れているんだね。
以前「変更が続くと一人で抱え込みやすい」と話していたことを踏まえると、
今は ①返事が必要なものを1件だけ選ぶ、②残りは明日返すと伝える、のどちらかが小さく始めやすそう。
今の余力だと、どちらがまだできそう？
```

過去の本人情報がない場合は「あなたに合うと分かっている方法ではなく、一般的な案」と明示します。提案を実行できないことを失敗として扱いません。

### 6.5 相談後の確認

会話の後に「役立った」「少し役立った」「合わなかった」「今は分からない」を選べるようにします。

- 評価だけでは新しい本人像を確定しない
- 「何が役立った／合わなかったか」を本人が話した場合は新しい根拠として扱う
- 1回の成功や失敗だけで恒久的な対処法へ固定しない
- 本人が確認した内容だけを「わたしのセルフケア」へ追加する

## 7. 安全性

ストレスへの気づきとセルフケアは役立つ一方、AI相談は医療や専門支援の代わりではありません。

- 症状名、病名、重症度を診断しない
- 服薬の開始・中止・変更を指示しない
- 不調が長引く、生活へ支障がある、自分で対処しにくい場合は専門家や相談窓口を案内する
- 自傷他害、虐待、差し迫った危険が疑われる場合は、通常のプロフィール参照とセルフケア提案を止める
- 危険時は一人で抱えず、現地の緊急窓口、医療機関、信頼できる人へ今すぐ連絡する行動を優先する
- 緊急時に長い質問、傾向分析、記録確認を続けない
- 安全経路へ切り替えたことを理由に、機微な推定をプロフィールへ自動保存しない

安全経路の分類と実装上の多層防御は[日記チャット実装設計 §8](../architecture/diary-chat-implementation-design.md#8-ガードレール)に従います。

セルフケア内容の運営上の参照先には、厚生労働省の[ストレスのサイン](https://www.mhlw.go.jp/kokoro/youth/stress/kokoro/kokoro_03.html)、[こころと体のセルフケア](https://www.mhlw.go.jp/kokoro/youth/stress/self/index.html)、[こころの耳](https://kokoro.mhlw.go.jp/)など、対象地域の公的機関が提供する情報を使用します。

## 8. 完了条件

- 負荷がかかりやすい場面、早めのサイン、合う・合わない対処、相談先を別の情報として確認できる
- 本人が話したこと、確認済みの仮説、診断からの手がかり、一般論を区別できる
- 確認済み情報がない項目を、AIの推定で埋めない
- サマリーまたは個別の傾向から「AIに聞く」を開始できる
- AIが現在の状況を過去のプロフィールより優先する
- AIの提案に、参照した本人情報と確かさ、実行負担の小さい選択肢が含まれる
- 本人が提案への評価と訂正を行い、その後の提案へ反映できる
- 不調が長引く場合と差し迫った危険がある場合に、通常のセルフケア相談から適切な案内へ切り替わる
- 削除・撤回された根拠と、本人が否定した仮説を助言へ使わない

## 9. この設計で決めないこと

- 医療的なストレスチェック、診断、治療計画
- ストレス度、危険度、Confidenceの数値表示
- 診断パラメータからストレス原因を自動確定する変換規則
- セルフケア情報をBrain Itemへ写像する具体的なモデル
- 相談窓口データの更新・地域判定・多言語化の実装
- AIモデル、プロンプト、API、データベース、通知の具体形
