## 背景

これまで `apps/worker/src/logic/feature/line.ts` の `buildReplyText` は、**すべてのテキストメッセージ**に対して「受け付けました。」＋ LIFF リンクを返していた（issue 15）。日記を送ったときにしかアンケートの入口が出てこないため、ユーザーが自分のタイミングでアンケートを開けなかった。

常設導線としてはリッチメニュー（issue 16）を予定しているが、キーワード返信はリッチメニューの画像・チャネル構成の確認を待たずに出せる。

## やったこと

1. `classifyLineText(text)` を logic 層へ追加し、`survey-request` / `diary` の union で返す（`handler/` は Queue との境界だけを持つ）
2. `buildReplyText(messageText, liffId)` が意図に応じて文面を組み立てる
   - `survey-request`: 「今日のアンケートに答える」＋ LIFF の URL だけを返す（受け付けた旨は付けない）
   - `diary`: 従来どおり「受け付けました。」＋ LIFF の URL
3. `LIFF_ID` 未設定時
   - `diary`: 既存方針どおりリンクを省き、受け付けた旨だけを返す
   - `survey-request`: 要求に応えられないため、設定の話はせず「いまはアンケートのリンクをお渡しできません。」と案内だけ返す
4. ログには日記の本文を出さず、判定結果 (`intent`) だけを残す
5. `.agents/rules/development.md` の「LINE Webhook 自動登録および日記の受付返信」へキーワード分岐の仕様を追記（返信文の仕様を所有する SSoT）
6. `logic/feature/line.test.ts` を更新し、`src/index.test.ts` へ Queue 経由の end-to-end も追加

## 決めたこと

### 日記の返信は変えない

[開発運用ルール §4](../../.agents/rules/development.md) は「返信には『今日のアンケート』への導線として LIFF の URL を添える」と定めており、[プロジェクト概要 §4](../../docs/project-overview.md#4-想定する利用体験) でも LINE は再訪の導線を担う。日記の返信からリンクを外すと、1 日 1 回のアンケートへの主要な再訪導線が消える。キーワードは**追加の入口**として足した。

§4 の「チャネルごとの役割分担」でも LINE は「アンケートの回答」について**リンクを配信する**役割であり、キーワードでリンクを返すのはこの範囲に収まる。よってプロジェクト概要の改訂は不要で、返信文の仕様を持つ `.agents/rules/development.md` だけを更新した。

### 表記ゆれは「正規化後の完全一致」まで

NFKC 正規化（全角英数・半角カナ・全角スペースを吸収）→ 前後空白の除去 → ひらがなをカタカナへ寄せる、の後にキーワード一覧（`アンケート` / `今日のアンケート` / `きょうのアンケート`）と**完全一致**するかで判定する。部分一致は採らない。

理由: 部分一致にすると「今日は会社でアンケートに答えた」のような**日記本文がコマンドとして飲み込まれ、記録されるべき日記が返信だけになる**。日記が主要な蓄積手段（[プロジェクト概要 §4](../../docs/project-overview.md#4-想定する利用体験)）なので、取りこぼしよりも誤判定を避ける側へ寄せる。取りこぼしは常設導線（issue 16）で補える。
