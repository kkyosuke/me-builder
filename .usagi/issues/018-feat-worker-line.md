## 背景

現状 `apps/worker/src/logic/feature/line.ts` の `buildReplyText` は、**すべてのテキストメッセージ**に対して「受け付けました。」＋ LIFF リンクを返す（#15）。日記を送ったときにしかアンケートの入口が出てこないため、ユーザーが自分のタイミングでアンケートを開けない。

常設導線としてはリッチメニュー（#16）を予定しているが、キーワード返信はリッチメニューの画像・チャネル構成の確認を待たずに出せる。

## やること

1. テキストメッセージの意図を判定する関数を `apps/worker` の logic 層へ追加する（`handler/` は HTTP / Queue の境界だけを持つ）
2. 「アンケート」と送られた場合はアンケート（LIFF）のリンクを返す
3. それ以外のテキスト（＝日記）の返信は**現状のまま**にする
4. `LIFF_ID` 未設定時は既存方針どおり安全に扱う（日記の返信はリンクを省く／アンケート要求にはリンクを出せない旨を返す）
5. `.agents/rules/development.md` の「LINE Webhook 自動登録および日記の受付返信」へキーワード分岐を追記する（返信文の仕様を所有する SSoT）
6. `apps/worker/src/logic/feature/line.test.ts` を更新し、新しい分岐のテストを追加する

## 決めたこと

### 日記の返信は変えない

[開発運用ルール §4](../../.agents/rules/development.md) は「返信には『今日のアンケート』への導線として LIFF の URL を添える」と定めており、[プロジェクト概要 §4](../../docs/project-overview.md#4-想定する利用体験) でも LINE は再訪の導線を担う。日記の返信からリンクを外すと、1 日 1 回のアンケートへの主要な再訪導線が消える。キーワードは**追加の入口**として足す。

§4 の「チャネルごとの役割分担」でも LINE は「アンケートの回答」について**リンクを配信する**役割であり、キーワードでリンクを返すのはこの範囲に収まる。よってプロジェクト概要の改訂は不要で、返信文の仕様を持つ `.agents/rules/development.md` だけを更新する。

### 表記ゆれは「正規化後の完全一致」まで

NFKC 正規化（全角英数・半角カナ・全角スペースを吸収）→ 前後空白の除去 → ひらがな／カタカナの差を吸収して、キーワード一覧と**完全一致**するかで判定する。部分一致は採らない。

理由: 部分一致にすると「今日は会社でアンケートに答えた」のような**日記本文がコマンドとして飲み込まれ、記録されるべき日記が返信だけになる**。日記が主要な蓄積手段（[プロジェクト概要 §4](../../docs/project-overview.md#4-想定する利用体験)）なので、取りこぼしよりも誤判定を避ける側へ寄せる。取りこぼしは常設導線（#16）で補える。
